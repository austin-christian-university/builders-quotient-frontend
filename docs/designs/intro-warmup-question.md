## Vision

### 10x Check
An adaptive warmup system where the orb analyzes the student's warmup response in real-time (latency, fluency, confidence signals) and adjusts subsequent exam pacing and encouragement accordingly. Way beyond current scope but represents the directional north star.

## Key Architectural Decision: Local-First Warmup

### Eng Review Simplification (2026-03-19)
The original CEO plan proposed uploading warmup videos to Storage BEFORE consent (requiring provisional sessions, deletion-on-decline, cleanup jobs, and TTL enforcement). The Codex-assisted eng review identified that keeping warmup recordings as local in-memory blobs until consent is accepted eliminates ~60% of the plan's complexity with zero functional loss.

### Current Flow
```
consent -> equipment check -> briefing orb -> vignette 1
```

### New Flow
```
equipment check (+ biometric consent checkbox)
    -> warmup (no session, blobs in memory)
    -> full consent gate
    -> createSession(consent)
    -> upload warmup blobs to Storage
    -> vignette 1
```

### How It Works
1. **No session during warmup.** The warmup page is purely client-side. No server actions, no session cookie, no database writes.
2. **Blobs stay in browser memory** until consent is accepted. If declined, blobs are discarded (never leave the browser).
3. **Session creation happens AFTER full consent**, using an extracted `createSession()` action that returns the session ID (no redirect).
4. **Warmup blobs uploaded after session creation** to `responses/{sessionId}/warmup_{n}.webm` via signed URLs.
5. **Client navigates** to `/assess/1` after upload completes (or best-effort on upload failure).

### Split Consent (BIPA/CUBI Compliance)
BIPA (Illinois) and CUBI (Texas) require informed consent BEFORE collecting biometric data.
1. **Pre-warmup (in equipment check):** Single biometric consent checkbox — "I consent to video/audio recording and biometric data collection during this assessment"
2. **Post-warmup (full consent gate):** Terms, Privacy Policy, detailed disclosures

Since warmup blobs never leave the browser until full consent is accepted, the legal risk is minimal. The biometric checkbox satisfies BIPA's "informed before collection" requirement for the local recording.

### Consent Decline Flow
If consent is DECLINED after warmup:
1. Discard all blobs (garbage collected automatically, never uploaded)
2. No session was created, no data persists
3. Clean exit for the student

### Warmup Resume Behavior
Warmup is **non-resumable**. If the student reloads or closes the tab, the warmup restarts from the beginning. The warmup is ~2 minutes of casual questions — this is trivially re-doable and avoids the complexity of persistence for a non-scored flow.

## Implementation Approach

## Design Specifications (added by /plan-design-review)

### Warmup Prompt Questions

Three prompts, ordered from easiest to most reflective. Tone: what a cool professor might ask on the first day of class — warm, curious, zero-stakes.

| # | Prompt Text | Think Time | Record Time | Design Intent |
|---|-------------|------------|-------------|---------------|
| 1 | "What's something you've built or created that you're proud of?" | 10s | 30s | Opens with competence. Connects to the "builder" theme. Easy to answer — everyone has built something. |
| 2 | "If you could start any business tomorrow, what would it be?" | 15s | 45s | Playful, forward-looking. Connects to entrepreneurship context without pressure. Longer record time because students get more expansive. |
| 3 | "What's one thing about you that most people wouldn't guess?" | 10s | 30s | Personal, fun, encourages authenticity. Ends on a light note before transition. |

### Phase-by-Phase Visual Spec

#### Phase A: Intro Orb

**Layout:** Full-screen dark background (identical to current briefing page). Layered ambient orb gradients + dot grid texture. AudioOrb centered vertically, captions below.

**Typography:** Captions use `text-[length:var(--text-fluid-base)] leading-relaxed text-text-primary/90 font-light` with staggered word reveal (same as current briefing).

**Controls:** Two pill buttons below captions after orb finishes speaking:
- Primary: "Let's Go" — `rounded-full border border-white/10 bg-white/5 px-8 py-5 backdrop-blur-md` with glow hover (same pattern as current briefing "Begin" button)
- Secondary: "Replay" — ghost button, left of primary

**Duration:** ~30s of narration. See Orb Script Copy section below.

**Journey map:** Visible at top of screen (see Journey Map section).

#### Phase B: Recording Prompts (×3)

**Layout:** Full-screen dark background continues (no page transition feel). Three zones stacked vertically:
1. **Top:** Journey map (persistent)
2. **Center:** Camera preview (aspect-video, `rounded-xl border border-border-glass`, mirrored `scaleX(-1)`) with prompt text overlaid below it
3. **Bottom:** Controls area

**Prompt display:**
- Eyebrow above prompt: `text-[length:var(--text-fluid-xs)] uppercase tracking-[0.3em] text-text-secondary` → "QUESTION 1 OF 3"
- Prompt text: `font-display text-[length:var(--text-fluid-xl)] font-semibold tracking-[-0.01em] text-text-primary` — centered, max-w-xl
- Fade-up entrance animation (`opacity: 0, y: 20px → opacity: 1, y: 0`, expo-out, 500ms)

**Think phase (10-15s):**
- Countdown ring (reuse VideoRecorder's SVG ring pattern): 120×120, stroke in `primary` blue
- Center text: "Think…" in `text-text-secondary` with countdown number below in `font-display tabular-nums text-text-primary`
- Camera preview visible but no recording indicator
- No controls — auto-advances to record phase

**Record phase (30-45s):**
- Recording indicator pill appears (top-right of camera preview): pulsing red dot + "REC" + timer in `tabular-nums`
- Same red glow shadow as VideoRecorder: `shadow-[0_0_20px_rgba(239,68,68,0.15)]`
- Countdown ring switches to red stroke, counting down remaining record time
- "I'm Done" button appears after 10s elapsed (same as VignetteExperience): `rounded-full border border-white/15 bg-white/5 px-6 py-2.5 backdrop-blur-sm`
- Auto-stops at time limit

**Between prompts:** Crossfade transition (300ms, opacity only). No jarring cut. Prompt text fades out, next prompt fades in. Camera preview stays continuous.

**Sub-progress:** The eyebrow "QUESTION 1 OF 3" / "QUESTION 2 OF 3" / "QUESTION 3 OF 3" provides wayfinding. No additional sub-progress bar needed — the journey map at top shows warmup section as active.

#### Phase C: Video Playback

**What plays:** The last recording only (prompt 3). By the third recording, the student is most comfortable — this is the version of themselves they should see.

**Layout:** Full-screen dark background. Video centered, `max-w-lg aspect-video rounded-2xl border border-border-glass` with ambient shadow. Glass card wrapper.

**Behavior:**
- Auto-plays with sound immediately upon entering phase (no tap required)
- Muted playback indicator if user's device was muted (respect system volume)
- Play/pause on tap/click of video area
- Replay button appears after playback completes

**Copy below video:**
- "Looking good! You've got the flow." in `font-display text-[length:var(--text-fluid-lg)] font-semibold text-text-primary`
- Fade-up entrance, delayed 0.3s after video starts

**Celebration micro-interaction:** Subtle gold glow bloom around the video card (`shadow-[0_0_32px_rgba(233,185,73,0.2)]`) that pulses once using `glow-pulse` animation. This is the emotional peak — the student should feel a moment of "I look good."

**Transition out:** "Continue" pill button below. On click, crossfade to Phase D.

#### Phase D: Transition Orb

**Layout:** Same as Phase A (full-screen, AudioOrb, captions). The orb reappears.

**Copy:** Shorter than intro (~15s). Bridges from warmth to formality. See Orb Script Copy section.

**Controls:** After orb finishes, text transitions to Phase E (consent) with a crossfade. No button — auto-advances after a 1s pause. The orb's final words prime the student for consent.

#### Phase E: Full Consent Gate

**Layout:** ConsentGate component rendered in a glass Card, centered on the same dark background (NOT the setup page's `min-h-dvh` centered layout — stays within the warmup full-screen context for continuity).

**Modification from current ConsentGate:** Remove the biometric checkbox (already accepted in equipment check). Keep Terms/Privacy and Video Recording checkboxes. Adjust heading from "Before We Begin" to "One Last Step" and subheading from "Consent & Disclosure" to "Review & Consent".

**Button text:** "Start the Assessment" (not "Continue to Equipment Check")

**Consent decline:** Below the consent button, a subtle text link: "I'd rather not continue" in `text-text-secondary hover:text-text-primary text-[length:var(--text-fluid-sm)]`. See Consent Decline section.

### Consent Decline Experience

When the student clicks "I'd rather not continue":

**Visual:** Crossfade to a centered card (glass surface, `max-w-md`). No orb, no decoration — clean and respectful.

**Copy:**
- Heading: "No problem at all." in `font-display text-[length:var(--text-fluid-2xl)] font-bold`
- Body: "Your practice recordings have been discarded — nothing was saved. If you change your mind, you can always come back and start fresh." in `text-text-secondary text-[length:var(--text-fluid-base)]`

**Action:** Single button: "Return Home" (`Button size="lg"`, primary blue, full width). Routes to `/`.

**Tone:** Respectful, reassuring, door is open. No guilt. No "are you sure?" confirmation — one click and done.

### Uploading State (Post-Consent Accept)

After consent is accepted and "Start the Assessment" is clicked:

**Visual:** Full-screen dark background with AudioOrb visible (breathing animation, gold-tinted glow to signal achievement/transition). No captions.

**Copy:** "Setting up your assessment…" in `font-display text-[length:var(--text-fluid-lg)] font-medium text-text-primary` centered below the orb.

**Duration:** Typically 3-5s (createSession + upload 3 blobs via signed URLs).

**Error handling:**
- If `createSession` fails: Show inline error alert (`rounded-xl border border-red-500/30 bg-red-500/10 px-4 py-3`) with retry button. "Something went wrong setting up your assessment. Please try again."
- If warmup blob upload fails: **Proceed anyway.** Warmup uploads are best-effort — the student should never be blocked from starting the real exam because a warmup video failed to upload. Log the failure for debugging.

**Key design decision:** No spinner. The orb's ambient breathing animation serves as the loading indicator. This maintains the calm, premium feel rather than switching to a utilitarian loading state.

### Journey Map

**Component:** New `WarmupJourneyMap` component (extends ProgressIndicator pattern).

**Placement:** Fixed at top of the warmup page, visible during all phases (A through E). Positioned at `top-0` with `py-3 px-4`, same container as current ProgressIndicator.

**Structure:** 4 labeled sections in a horizontal bar:

```
[ Warmup ] [ Practical (2) ] [ Creative (2) ] [ Done ]
```

**Visual treatment:**
- Each section is a `rounded-full` segment in the bar (not individual dots)
- Current section: `bg-secondary` (gold) — matches existing ProgressIndicator's "current" color
- Future sections: `bg-border-glass` — barely visible, same as existing "future" segments
- Completed sections: `bg-primary` (blue) — same as existing "completed" segments
- Section labels: `text-[length:var(--text-fluid-xs)] text-text-secondary` below each segment, hidden on mobile (segments only, no labels — too cramped at 375px)
- Transitions: `transition-colors duration-500` (same as existing)

**Accessibility:** `role="progressbar"` with `aria-label="Assessment progress: Warmup"`. Updates aria-label as sections complete.

**During exam (post-warmup):** The existing ProgressIndicator continues to show step-level progress (1/4, 2/4, etc.) as it does today. The journey map is warmup-only — it orients the student to the full assessment shape before they begin.

### Biometric Consent Checkbox (Equipment Check)

**Placement:** Below the device status indicators, above the requirements list. Inside a highlighted container to draw attention.

**Container:** `rounded-xl border border-accent-gold/20 bg-accent-gold/5 px-4 py-4` — gold-tinted to signal importance without alarm.

**Checkbox:** Reuses the exact Checkbox component from ConsentGate (same custom appearance-none styling).

**Label text:** "I consent to video and audio recording, including biometric data collection, during this assessment." with inline link: "Learn more" → opens `/biometric-policy` in new tab, styled with `legalLinkClass` from ConsentGate.

**Validation:** If student clicks "I'm Ready" without checking the biometric box:
- Inline error below checkbox: `text-[length:var(--text-fluid-sm)] text-red-300` → "Please accept to continue"
- Button stays enabled (per CLAUDE.md: "allow submitting incomplete forms to surface validation")
- Focus moves to the checkbox on error

**Equipment check button text change:** "I'm Ready" → navigates to `/assess/warmup` (client-side `router.push`, no server action).

### Orb Script Copy

#### WARMUP_INTRO_SCRIPT (~30s)

**Tone:** Warm, casual, encouraging. Like a friendly coach. Slightly shorter than the current PRE_EXAM_SCRIPT because the student hasn't committed yet — keep it light.

**Draft captions (to be refined with actual audio recording + ElevenLabs word timings):**

```
Caption 1 (0s–12s):
"Welcome to the Builder's Quotient! Before we dive into the real questions, I want to help you get comfortable with the camera. We're going to do a quick warmup — just three casual questions to get you warmed up."

Caption 2 (13s–22s):
"There are absolutely no wrong answers here. These aren't scored or graded — they're just for you to get a feel for how this works. Talk naturally, like you're chatting with a friend."

Caption 3 (23s–28s):
"You'll see each question, get a few seconds to think, and then record your answer. Simple as that. Ready?"
```

#### POST_WARMUP_SCRIPT (~15s)

**Tone:** Encouraging but transitional. Bridges the warmth into formality.

**Draft captions:**

```
Caption 1 (0s–8s):
"Nice work! See, nothing to it. You're a natural on camera. Now, before we start the real assessment, I need you to review a few quick details."

Caption 2 (9s–14s):
"Take a moment to read through the information below and check the boxes when you're ready."
```

### Responsive Behavior

**Desktop (≥768px):**
- Camera preview: `max-w-lg aspect-video`, centered
- Prompt text: `max-w-xl`, centered below camera
- Journey map: labeled segments
- Consent gate: `max-w-2xl` card, centered

**Mobile (<768px):**
- Camera preview: full-width with `px-4` padding, `aspect-video`
- Prompt text: below camera, `px-4`, `text-[length:var(--text-fluid-lg)]` (smaller than desktop xl)
- Journey map: segments only, no labels (too cramped)
- Controls: pinned to bottom of viewport with `pb-[env(safe-area-inset-bottom)]`
- Consent gate: full-width card, scrollable content area
- Video playback (Phase C): full-width video, copy below

**Memory management:** 3 recordings × 45s max = ~50-100MB in blobs. This is within iOS Safari's per-tab memory budget (~1GB on modern devices, ~300MB on older). Accepted risk — warmup is short and blobs are released immediately after upload or decline. If a blob fails to create (out of memory), skip that recording gracefully and proceed to the next prompt.

### Focus Management & Accessibility

**Phase transitions:** Each phase transition moves focus to the primary interactive element:
- `intro_orb` → focus on "Let's Go" button when orb finishes
- `recording_1/2/3` → focus on prompt text container (announced to screen readers)
- `playback` → focus on "Continue" button
- `consent` → focus on first unchecked checkbox
- `uploading` → announce "Setting up your assessment" via `aria-live="polite"`
- `done` → focus managed by navigation to `/assess/1`
- `declined` → focus on "Return Home" button

**`aria-live` region:** A single `aria-live="polite"` region at the page level announces phase transitions:
- "Warmup question 1 of 3: What's something you've built or created that you're proud of? Think time: 10 seconds."
- "Recording. Speak whenever you're ready."
- "Warmup question 2 of 3…" etc.
- "Playing back your recording."
- "Review and consent."

**Reduced motion:** All crossfade transitions collapse to instant cuts. Orb falls back to static gradient. Gold glow celebration on playback is a static gold border instead. Think/record countdown uses numeric display only (no animated ring stroke).

### Camera/Mic Failure During Warmup

If the camera or microphone disconnects during warmup (MediaStream track ends unexpectedly):

1. Pause the current phase
2. Show an inline alert: "Your camera or microphone disconnected. Please check your device and try again."
3. "Retry" button re-requests `getUserMedia`
4. On success: resume the current prompt (do NOT restart from the beginning)
5. On repeated failure: "Return to Equipment Check" link → navigates to `/assess/setup`

This reuses the same error patterns from the equipment check page (same alert styling, same retry flow).

### Back/Forward Button Behavior

- Warmup is a single route (`/assess/warmup`). All phases are React state, not URL segments.
- Browser back from warmup → navigates to `/assess/setup`. This is correct — warmup restarts on re-entry (non-resumable).
- Browser forward after going back → navigates to `/assess/warmup` (fresh start).
- No `history.pushState` between phases — phases are internal state transitions, not navigable states.
- `beforeunload` warning during active recording: "You have an active recording. Are you sure you want to leave?"

## Security Considerations
- No data leaves the browser before consent — biometric consent checkbox covers local recording
- Session only exists after full consent — all downstream routes implicitly enforce consent via session cookie
- Warmup blobs are transient client-side state — no server-side cleanup needed on decline
- Upload rate limiting via existing session creation gates
- `beforeunload` prevents accidental navigation during recording
